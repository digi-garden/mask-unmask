# 実装フェーズ3：例外処理・動作検証 (Week 3)

本ドキュメントは、実装フェーズ3（表記揺れ吸収の調整、セキュリティ (CSP) 設定の検証、E2Eテスト、Lighthouseによる性能測定、および型チェックと本番ビルド検証）におけるタスク詳細と手順を定義します。

---

## 1. 実施タスク & 手順

### 1.1. 表記揺れ吸収ロジックのチューニング
1. **空白・大文字小文字の揺らぎ判定の実装:**
   * AIの出力に含まれる `[ cn_custom _ 0001 ]` や `[cn_custom_0001]` などの表記揺れ（大文字小文字の違い、角括弧やアンダースコア前後の空白）を正しく `[CN_CUSTOM_0001]` にマッピングする正規化ロジックの検証・調整。※仕様で許容されていない `[CN_CUSTOM-0001]` (ハイフン置き換え) などのタグは非許容として正しく弾くこと。
   * **制限範囲:** 括弧とカテゴリ、番号の間の空白のみを許容し、部分一致や通常テキストへの誤置換を防ぐ完全一致ロジックの安全性を担保。
2. **表記揺れのテストデータによる検証:**
   * 許容仕様の範囲内（大文字小文字・空白のみの揺らぎ）のテストデータを対象にした際、元テキストへの復元率が100%になることを検証。

### 1.2. セキュリティ (CSP) の検証
1. **`connect-src 'none'` の適用確認:**
   * ※注意: `Vite preview` などの通常の静的ローカルプレビューサーバーは `_headers` に記載されたヘッダー情報を解釈して送出しないため、CSPの実ヘッダー遮断動作の検証は、Cloudflare Pagesへのプレビューデプロイ環境、またはローカルで同等のカスタムHTTPヘッダーを送出できるテストサーバー（例: Wrangler Pages dev 環境、または同一的CSPヘッダーを設定できる http-server）を用いて検証する。
   * アプリ動作中に Fetch、XHR、WebSocket などを利用した外部へのいかなるネットワークリクエストもブラウザのセキュリティポリシー（CSP）によって遮断されることを確認する。
2. **`base-uri 'none'` の適用確認:**
   * `<base>` タグの挿入によるURL解決の改変リスクがブロックされることを確認。
3. **`public/_headers` 成果物の検証:**
   * `npm run build` 実行後、`dist/` ディレクトリ内に正しく `_headers` が配置され、ヘッダー情報に確定した CSP とセキュリティヘッダー（`X-Content-Type-Options: nosniff` 等）が書き込まれていることを確認。

### 1.3. Playwright による E2E テストの実装 (`tests/e2e/unmaskFlow.spec.ts`)
1. **Mask ➔ Unmask 全体フローテスト:**
   * 入力テキスト投入 ➔ 自動仮名化 ➔ 置換マップ登録確認 ➔ コピー ➔ Unmaskタブ遷移 ➔ AI回答模倣テキスト（タグ入り）投入 ➔ 復元テキスト表示 ➔ 元データと完全に一致していることの検証。
2. **画面幅（レスポンシブ）テスト:**
   * ビューポート幅を 767px に縮小した際に、PC専用UIが自動で非表示になり、クリアボタンが全幅で表示されることの確認。

### 1.4. 自動性能テストの構築 (`src/utils/maskEngine.perf.test.ts`)
1. **性能アサーションの実装 (`npm run test:perf`):**
   * 100KB固定テストデータ（APIキー、IP、Email、電話番号、カスタム単語が多数埋め込まれたダミーテキスト）を定義。
   * 10回のウォームアップ空実行後、100回連続でMask処理を実行。
   * 測定時間を昇順ソートしてp95値（95パーセンタイル）を算出。
2. **動作環境に応じた判定ロジック:**
   * 基準環境（ローカル開発PC）では、p95値が50ms以下であることを自動アサーションでテスト合否判定。
   * 不特定のCI環境（スペックが固定されていないため）では、テストを強制エラーとせず、計測結果のコンソール出力および回帰監視ログへの記録のみを実行する設定とし、CIパイプラインの不安定化を防ぐ。

## 2. 最終検証 & 品質保証手順

本番デプロイ直前のビルドおよび品質チェック手順です。

### 2.1. 静的検証 & ビルド実行
1. **型チェック実行:**
   ```bash
   npm run type-check
   ```
   コンパイルエラーや型定義の不整合が0件であることを確認。
2. **本番ビルドの実行:**
   ```bash
   npm run build
   ```
   ビルドが警告なしで成功し、静的ファイル（JS、HTML、CSS、および `_headers`）が正しく出力されることを確認。成果物のサイズを確認し、不要なパッケージが混入していないかを確認。

### 2.2. ブラウザ検証 (Lighthouse)
本番同等のローカル静的サーバー（`npm run preview` 等）を立ち上げ、Chromeの Lighthouse で品質スコアを検証します。
* **アクセシビリティスコア:** `100`（または90以上）をマークしていること。
* **コントラスト比の検証:** WCAG 2.1 Level AA に準拠したコントラスト比（4.5:1以上）をテキストと背景が満たしていることを確認。
* **パフォーマンス評価:** FCP (Fast 3G想定で1.5秒以下)、LCP (2.0秒以下) を満たしていることを確認。
* **ネットワーク通信検証:** デベロッパーツールの Network タブを開き、操作中に外部リクエストが0件（接続遮断）であることを確認。
