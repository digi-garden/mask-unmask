# MU-COMP-006 ブランド識別と製品UI配色の適合判定

## 結論（統合ブランチにおける技術的是正）

**正式なブランド識別色と、Mask & Unmaskの機能UI色は別の用途であり、ブランドガイドラインは機能UIの全背景・全ボタンをブランド基本4色へ変更することを要求していない。** 既存のダーク／emeraldの操作UIを変更する代わりに、提供元ロゴは正式カラーのSVGを改変せず、公式オフホワイト背景で使用する。現行の配色をブランド正式色の変更やブランドロゴの例外として扱わない。

この判定の根拠は固定版 `digi-garden/brand-assets` commit `31bf40e921661c9c8e7b246434b349ad71c7c578` の `guidelines/digi-garden-brand-guidelines.md` 第5〜10節と、`guidelines/digi-garden-standards-index-v1.0.md` 第1・5節。

## 実装の用途区別

| 分類 | 実装・制御 | 上位規約との関係 |
|---|---|---|
| 正式な識別カラー | `tailwind.config.js` の `identity.primary=#216B73`、`identity.accent=#F29A65`、`identity.background=#FAFAF8`、`identity.inverse=#153F44` | ブランドガイドラインの4色を独立トークン化。今後ブランド表現を編集する場合もこれらの意味を変更しない |
| 製品機能UI | 従来の `brand.bg=#0f172a`、`brand.primary=#10b981` 等 | 仮名化、復元、フォーカス等の機能画面用の配色。従来トークン名は互換性のため維持し、正式ブランドカラーと混同しない |
| 提供元ロゴ | `public/digi-garden-logo.svg` をそのまま `img` で参照 | SVGの色・形・文字間などを変更しない。横組みロゴを再構成しない |
| ロゴの表示背景 | `src/App.tsx` のロゴリンク領域に `bg-identity-background` を使用 | 正式ロゴを明るい背景に置くというガイドライン第6・8節の指針に対応 |
| ロゴ最小表示幅 | 高さ20pxの原本の自然縦横比による横幅約87.5px | ガイドライン第5.2節の推奨80px以上を満たすことを自動検査 |
| フォーカス・UIアクセシビリティ | 従来の機能色を保持、主要文字のコントラスト検査を維持 | UI操作の回帰を抑制。代表領域のテストはWCAG 2.2 AAの全面認証ではない |

## 例外判定

**正式ブランド要素に対する配色例外を申請する必要はない**、という条文解釈を採る。理由は、ガイドライン第7節が「用途／色名」を示す一方、機能UIの全色をブランド4色に限定するとの明文はなく、製品側のダーク操作UIが正式なロゴ・ワードマーク・基本色定義を改変していないため。なおロゴ表示については明るい無地領域を用いる。

これは**上位規約を変更したり、明示されたロゴの禁止事項を緩和する例外承認ではない**。製品責任者が「機能UIにもブランド基本色の全面適用が必要」と解釈する場合は、この判定を差し戻して例外承認または再配色を選ぶこと。以前の「配色例外候補・未承認」という評価は、ブランド正式色とUI用色の区別が不明確だったことによる暫定評価として上書きする。

## 確認と最終判定の範囲

- `tests/e2e/brand-identity.spec.ts` は375px/1280pxで提供元ロゴのURL、画像読み込み、最小横幅、白系の背景色を検査する。
- `tests/e2e/accessibility.spec.ts` は既存代表領域の文字コントラストと見出し階層を継続検査する。
- 実アセットが正式ブランド管理資産と一致するかは、公式リポジトリの素材ハッシュや配布履歴を照合して別途確認する（ブランドロゴの見た目だけでは同一性の証明にならない）。
- **MU-COMP-006のコード・UI用途分離としての是正はCI合格後に完了**。最終リリースのGate A/Bと公開後確認は別途行う。製品責任者による異なる上位規約解釈が示された場合は再判定する。

以降のブランドUI検討では、正式ブランド識別と製品固有の機能色を設計上明示し、色の意味を混同しない。
