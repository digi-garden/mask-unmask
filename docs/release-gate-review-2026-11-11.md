## 次回判定を可能にする残作業（必要なものだけ）

1. **技術側（可能な限り自動）**：公開候補SHA凍結後にCI、依存/機密混入、配布物、主要ブラウザ動線、最終README/リリース文言を確認し、URL・ログ・SHAを残す。
2. **権限者判断（外部から代行不能）**：AIサービスの実契約・データ保持・学習設定・共有条件と、非公開入力の分類を非公開で確認。埋込フォント/ロゴ・その他素材の原本・許諾根拠を検証。クラウド管理画面で本番停止/復旧権限と未実証の許容可能性を判断する。
3. **正式再審査**：Gate Aの重要NOT_RUNを証跡で解消できたときのみ、`PASS`／理由付き`N/A`へ変更し、リリース責任者が`main`への公開を承認する。
4. **公開後のみ**：新CloudflareデプロイIDの記録、`npm run verify:production`、`npm run verify:production:browser`、`npm run verify:production:oss`を同一のリリース候補と照合。公開後のみ成立する確認を事前Passと書かない。

## 審査完了と公開を区別する

- **Gate A/B審査作業：完了**（すべての16事項に正式な判定値・理由・証拠を付与）
- **Gate A適合：未達**（重要なNOT_RUNあり）
- **公開判定：リリース不可**
- **本番への反映：未実施**（`main`、Cloudflare Pages、WAF、DNSに変更なし）

新しい証跡なしにNo-GoをYesへ変更しない。審査後に文書だけをマージする場合も最終ソースSHAは変わるため、最終候補のCI/コミットを再確認する。
