# 実装フェーズ1：環境構築 & コアロジック実装 (Week 1)

本ドキュメントは、実装フェーズ1（環境構築、コア仮名化・復元エンジン、バリデーションロジック、永続化フックの設計と実装）におけるタスク詳細と手順を定義します。

---

## 1. 実施タスク & 手順

### 1.1. 開発環境の初期セットアップ
1. **Vite プロジェクトの生成:**
   * `mask-unmask` プロジェクトルートディレクトリにて、TypeScript テンプレートを用いて Vite プロジェクトを非インタラクティブモードで初期化。
2. **依存関係のインストール:**
   * 必要なパッケージ（React, TypeScript, Tailwind CSS, Vitest 等）を追加。
   * バンドルサイズ最小化と脆弱性対策のため、Ajv 等の巨大スキーマバリデータや外部 Web フォントパッケージは一切導入しない。
3. **Tailwind CSS の適用:**
   * `@import "tailwindcss";` を用いて、システム等幅フォントおよび Slate/Zinc 系のダークカラーテーマ、エメラルドグリーン（`#10B981`）のアクセントを設定。
4. **public/_headers の作成とCSP設定:**
   * `public/_headers` ファイルを新規作成。connect-src 'none', base-uri 'none' を含む確定したCSPディレクティブおよび、X-Content-Type-Options: nosniff などのセキュリティヘッダーを記述。
   * Viteビルド後に成果物ディレクトリ `dist/_headers` へ正しくコピーされることの簡易検証スクリプトの設定。

### 1.2. コア仮名化・復元エンジン (`src/utils/maskEngine.ts`) の実装
1. **RegExp の安全な生成:**
   * `CN_TAG_REGEX` の `lastIndex` 汚染を防ぐため、実行の都度新しい RegExp インスタンスを返す、または `matchAll` を使用するスキャン関数を実装。
2. **自動検出正規表現の定義:**
   * `APIKEY` (OpenAI, AWS, GitHub), `IPV4`, `IPV6`, `EMAIL`, `PHONE` の正規表現を厳密に定義。
3. **一括競合解決 (Conflict Resolution) ロジック:**
   * `DetectionMatch` 配列を作成し、以下の決定性優先度でフィルタリングする一括競合解決を実装：
     1. 来歴優先 (`CUSTOM` / `IMPORT` ➔ `AUTO`)
     2. 最長一致優先 (`end - start` の降順)
     3. カテゴリ優先 (`APIKEY` ➔ `EMAIL` ➔ `PHONE` ➔ `IPV6` ➔ `IPV4`)
     4. 開始位置優先 (`start` の昇順)
     5. タグ名の辞書順優先
4. **位置ベースの Mask スライシング再構築:**
   * 競合解決後のマッチを開始位置順にソートし、非重複を検証したうえで、入力テキストのスライシングと置換タグの連結によってテキストを一度だけ再構築する。
5. **位置ベースの Unmask スライシング再構築:**
   * `CN_TAG_REGEX` で抽出したタグの表記揺れ（大文字小文字、空白）を標準化し、入力テキスト内のインデックス位置を元に、一度だけ `original` のテキストへ復元して連結再構築する（二重復元の防止）。

### 1.3. カスタムバリデータ & ファイルI/Oの実装 (`src/utils/validator.ts`, `src/utils/mapFileService.ts`)
1. **JSON Schema の全制約検証:**
   * 自作の軽量バリデータで、`const`, `format`, `pattern`, `minLength`, `maxLength`, `enum`, `additionalProperties: false`, `maxItems: 1000` を含むスキーマの全制約を漏れなく検証。
2. **一貫性バリデーション:**
   * 各要素の `tag` 内のカテゴリ名と `category` プロパティ値の完全一致を検証。
3. **ファイルI/Oとトランザクション:**
   * `FileReader`（UTF-8）の読み込み、500KB制限の事前チェック。
   * エクスポート用 JSON の生成（`version`, `createdAt` の付与、`source` の除外）。
   * メモリ上での検証完了後に React State と sessionStorage を一括更新するトランザクション構造。 Blob URL 生成と `URL.revokeObjectURL()` によるメモリ解放。

### 1.4. 原子的永続化フック (`src/hooks/usePersistedState.ts`) の実装
1. **単一エンベロープ保存 (`PersistedAppState`):**
   * 状態を一つにまとめ、単一のキー `cn_app_state` で JSON 文字列として `sessionStorage` に書き込み。
2. **QuotaExceededError ハンドリング:**
   * 書き込み失敗時にキャッチしてロールバックし、React State を変更しない。
3. **互換性チェック:**
   * ロード時に `version: 1` チェックを行い、不一致時はクリアしてデフォルト初期化。

## 2. ユニットテスト計画 (Vitest)

コアエンジンの動作を検証するため、以下のテストケースを作成・実行します。

* **自動検出正規表現テスト:**
  * OpenAI キー（`sk-proj-[a-zA-Z0-9]{40,}`）のダミー値が正しくマッチし、短い文字列が除外されること。
  * IPV4, IPV6 (省略表記、角括弧、ゾーンID含む)、電話番号（ハイフン有無、国際表記）が期待通りマッチすること。
* **競合解決 & 連番採番テスト:**
  * 重複や交差がある場合、タイブレークルールに従って競合が解決すること。
  * `9999` 上限に達した際にアサーションエラーが検知されること。
* **スライシング再構築 & 二重復元防止テスト:**
  * 復元された値の中に別のタグ文字列が含まれていても、再置換されずに1回のみ正しく元の文字列に復元されること。
* **カスタムバリデータテスト:**
  * JSON Schema の各制約（未知フィールド、最大件数1000、タグ不一致など）に反する不正な JSON を検知してエラーを返すこと。
* **ロールバックテスト:**
  * `sessionStorage` への書き込み時に `QuotaExceededError` が発生した際、React State が書き換えられないこと。
* **状態ライフサイクルの網羅テスト:**
  * トグルOFF、または入力テキストから消えた場合に `source: "AUTO"` マップアイテムが削除されること。
  * `source: "CUSTOM"` / `"IMPORT"` マップアイテムが入力テキストから消えても保持されること.
  * (※UI状態に依存する個別削除後の一時除外および入力変更時の解除ライフサイクルは、Phase 2へ移管)
  * 既存タグ形式（`[CN_..._...]`）入力時にMaskを中断（警告表示）すること。
  * 壊れた/旧バージョンデータのセッション永続化データを検知した際の初期化処理。
  * タグと `category` の不一致データの検知および却下。
  * インポートマージ競合時のリナンバリングと重複統合の処理。
